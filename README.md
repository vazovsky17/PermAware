# PermAware

> Разрешения под контролем

Android-приложение, которое показывает, у каких ваших программ есть доступ к камере, микрофону,
местоположению и контактам, какие из этих разрешений выданы на самом деле, и **что изменилось с
прошлой проверки**.

Всё считается на устройстве. Ни сервера, ни учётной записи, ни рекламы, ни аналитики — и нет
разрешения `INTERNET`, так что отправить список ваших приложений куда-либо приложение физически
не может.

| | |
|---|---|
| Пакет | `app.vazovsky.permaware` |
| Язык и интерфейс | Kotlin, Jetpack Compose, Material 3 |
| minSdk / targetSdk | 28 / 36 |
| Проверено на | Samsung Galaxy A17 (SM-A175F), Android 16, 473 пакета |
| Тесты | 81 на JVM, 113 на устройстве, lint и ktlint чистые |
| Языки | русский, английский |
| Размер | APK 4,2 МБ, AAB 5,1 МБ |

## Чего оно не делает

Это не антивирус, не сканер вредоносов, не файрвол, не VPN и не рут-тулза. Приложение никогда не
называет программу вредоносной из-за её разрешений. Разрешения — не улика: большинству программ
доступ нужен по делу. Задача продукта в другом — сделать этот доступ **видимым** и заметить, когда
он меняется.

## Приватность

Это главное, ради чего всё затевалось, и держится оно на устройстве кода, а не на обещаниях.

* **Нет разрешения `INTERNET`.** Проверено по смёрженному релизному манифесту. Передать наружу
  нечего и нечем.
* **Нет SDK аналитики, рекламы, атрибуции и сбора падений.** Весь граф зависимостей — AndroidX,
  Kotlin и Hilt.
* Нет учётной записи и нет бэкенда.
* Результаты проверок лежат в приватной базе Room; облачный бэкап и перенос на новое устройство
  отключены.
* От удалённого приложения остаётся только то, что уже было в строке истории: последнее известное
  название, имя пакета и версия. Когда срок хранения истечёт, исчезнет и это. Отдельного архива
  «что у вас когда-то стояло» нет.
* Единственное действие наружу — `ACTION_VIEW`, который запускает сам пользователь, и никаких
  данных к нему не прикладывается.
* Экспорт отчёта делает человек своими руками, через системный лист «Поделиться».

## Что Android вообще позволяет узнать

Система многое прячет от сторонних приложений. Всё, на что опирается PermAware, было **измерено на
живом устройстве** до того, как написали первый экран.

| Возможность | Как на самом деле |
|---|---|
| Запрошенные разрешения и **состояние выдачи** | Читается полностью. На этом стоит весь продукт |
| Уровень защиты разрешения, чужие разрешения | Читается полностью |
| Специальные возможности, слушатель уведомлений, администратор устройства, белый список батареи | **Включено или нет — читается** через документированные API |
| Поверх других окон, установка неизвестных, доступ к статистике, ко всем файлам, запись настроек | Закрыто через AppOps. На части устройств читается, на остальных сообщаем «заявлено, состояние неизвестно» — **но не угадываем** |
| Активна ли VPN прямо сейчас | Недоступно. Видно только объявление в манифесте |
| Слежение за разрешениями в реальном времени | Недоступно без постоянной службы переднего плана, а её приложение не использует принципиально |

Там, где состояние установить нельзя, интерфейс так и пишет — «Не удалось определить» — и объясняет
почему. Это требование к продукту, а не недоработка, которую надо обойти.

### Про `QUERY_ALL_PACKAGES`

Приложение объявляет `android.permission.QUERY_ALL_PACKAGES`. Это измерено, а не предположено: один
и тот же зонд прогнали дважды, поменяв только манифест.

| Манифест | Видно пользовательских приложений |
|---|---|
| С разрешением | **53** |
| Без него | **2** (само приложение и его тестовый APK) |

Элемент `<queries>` не умеет выражать «всё, что человек себе поставил», а это ровно то, ради чего
продукт существует. Заметное уведомление показывается на последней странице знакомства, до первой
проверки — именно такой порядок требует политика Play.

## Как устроено

Один модуль `:app` со строгими границами между пакетами. Разносить восемь пакетов по восьми
Gradle-модулям на таком размере — это плата за сборку без всякой отдачи; границы, которые
действительно важны, держатся направлением зависимостей, а не стенами между модулями.

```
app/src/main/java/app/vazovsky/permaware/
├── core/config/        AppLinks — единственное место, где вообще может быть URL
├── core/util/          TimeProvider: подменяемые часы, чтобы проверка и хранение тестировались
├── domain/
│   ├── model/          Чистый Kotlin. Ни одного типа из Android
│   ├── permission/     PermissionCatalog — офлайновая база знаний о разрешениях
│   ├── attention/      AttentionEngine и PrivacyOverviewCalculator, оба чистые
│   ├── diff/           SnapshotDiffer — движок «что изменилось»
│   └── export/         ReportBuilder
├── data/
│   ├── platform/       ЕДИНСТВЕННОЕ место, где трогают PackageManager
│   ├── db/             Room: проверки, снимки, события изменений
│   ├── prefs/          DataStore
│   └── repository/     ScanRepository — источник истины, пока приложение живёт
├── scan/               ScanPipeline, ScanWorker, BackgroundScanScheduler, PackageChangeObserver
├── ui/                 theme/ components/ navigation/ screens/ и common/ для строк
└── di/                 модули Hilt
```

**Главная граница — `data/platform`.** `PackageInfo`, `ApplicationInfo` и `PermissionInfo` из неё не
выходят: наверху живёт только `InstalledApp`. Поэтому движки внимания, диффов и отчётов гоняются
обычными JVM-тестами, а весь интерфейс проверяется на фикстурах, без единого обращения к устройству.

Конвейер проверки: прочитать видимые пакеты → разобрать разрешения → определить особый доступ →
оценить внимание → свести сводку по устройству → сравнить с прошлым снимком → сохранить всё одной
транзакцией → применить срок хранения. Всё вне главного потока, около 1,5 секунды на 473 пакета.

## Сборка

Нужны JDK 17, Android SDK с API 36 и устройство или эмулятор с API 28 и выше.

```bash
./gradlew :app:assembleDebug
./gradlew :app:installDebug
```

Релиз:

```bash
./gradlew :app:assembleRelease
./gradlew :app:bundleRelease
```

### Подпись

Ключ живёт в `signKeystore/` — сам keystore и `key.properties` рядом с ним, четыре значения:

```properties
RELEASE_STORE_FILE=permaware-upload.jks
RELEASE_STORE_PASS=…
RELEASE_ALIAS=permaware-upload
RELEASE_KEY_PASS=…
```

В CI те же четыре значения приезжают переменными окружения `PERMAWARE_KEYSTORE_PATH`,
`PERMAWARE_KEYSTORE_PASSWORD`, `PERMAWARE_KEY_ALIAS`, `PERMAWARE_KEY_PASSWORD`. Источник
засчитывается только целиком; окружение выигрывает у файла, когда заполнены оба.

Если ключа нет вовсе, релиз соберётся **неподписанным, и сборка об этом скажет** — установить такой
APK нельзя, так что за готовый артефакт его никто не примет. А вот наполовину заполненную
конфигурацию `verifyReleaseSigning` валит намеренно: иначе релиз тихо уехал бы на отладочном ключе,
который может сделать кто угодно.

`.gitignore` исключает и каталог целиком, и `*.jks`, и `key.properties`. **Держите резервную копию
ключа и пароля офлайн, вне репозитория** — потеряете, и ни одну установленную копию обновить уже не
выйдет. Проверить подпись:

```bash
apksigner verify --print-certs app/build/outputs/apk/release/app-release.apk
```

## Проверки

```bash
./gradlew :app:ktlintCheck                # стиль
./gradlew :app:lintRelease                # должен быть чистым
./gradlew :app:testDebugUnitTest          # 81 тест на JVM, устройство не нужно
./gradlew :app:connectedDebugAndroidTest  # 113 тестов, нужен прибор
```

Первые три гоняет GitHub Actions на каждый push и pull request, там же собирается релиз. Ключа в CI
нет, и это нормальный случай, а не сломанный: собирается неподписанный APK. Инструментальные тесты
в CI не ходят — им нужно устройство, и эмулятор на 113 тестов превращает пятиминутный прогон в
получасовой.

UI-тесты никогда не читают настоящий `PackageManager`: `TestPlatformModule` подставляет фиксированный
набор фикстур, поэтому тест, который прошёл на телефоне, пройдёт и на чистом эмуляторе.

В инструментальном наборе лежат ещё и **зонды возможностей** — те самые, которыми измеряли таблицу
выше. Это исследовательские инструменты, они оставлены в репозитории, чтобы выводы можно было
перепроверить на новом устройстве или новой версии Android:

```bash
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=app.vazovsky.permaware.probe.CapabilityProbeTest
adb logcat -s PWProbe PWProbe2 PWVis PWScan
```

## Что где менять

| Что | Где |
|---|---|
| Ссылки наружу | `permaware.boostyUrl`, `permaware.githubUrl`, `permaware.contactUrl` в `gradle.properties` → `core/config/AppLinks.kt`. Не задана — то, что на неё опирается, в релизе просто не показывается |
| Название и слоган | `R.string.app_name` и `R.string.app_tagline`. Больше имя продукта нигде не пишется |
| Цвета, отступы, шрифты | `ui/theme/`: `Palette.kt` — сырые значения, `Tokens.kt` — смысловые роли, `Typography.kt` |
| Веса и пороги внимания | `domain/attention/AttentionEngine.kt`, все константы наверху файла |
| Веса балла приватности | `domain/attention/PrivacyOverviewCalculator.kt` |
| База знаний о разрешениях | `domain/permission/PermissionCatalog.kt` и `res/values*/strings_permissions.xml` — править вместе |
| Картинки | `mipmap-*` — иконка, `drawable-*` — заставка, иллюстрации знакомства и портрет для «О приложении». Исходники лежат вне репозитория |

## Локализация

Приложение говорит по-русски и по-английски. Все видимые строки лежат в ресурсах: в композаблах нет
строковых литералов, а доменные перечисления превращаются в строки ровно в одном файле —
`ui/common/Labels.kt`.

| | |
|---|---|
| `res/values/` | русский, локаль по умолчанию |
| `res/values-en/` | английский |
| `res/xml/locales_config.xml` | обе локали; из этого файла Android строит выбор языка для приложения |
| `androidResources.localeFilters` | они же, чтобы в APK не уехало лишнее |

Английский написан как английский интерфейс, а не переведён построчно: слоган «Разрешения под
контролем» по-английски звучит «Know what your apps can access», а не «Permissions under control».
Название PermAware не переводится никогда. Уровни внимания — Low / Moderate / Elevated, и *внимание*
единственное слово для этого понятия: ни риска, ни опасности, ни угрозы.

Русский использует все четыре формы множественного числа, английский — две. Любое число, которое
видит человек, идёт через ресурс plurals: счёт, собранный конкатенацией, по-русски читается прилично,
а по-английски ломается ровно на единице.

Третий язык — это `res/values-xx/strings.xml`, оба файла со строками, и локаль, добавленная **и** в
`locales_config.xml`, **и** в `localeFilters`. Объявить локаль и не перевести её до конца хуже, чем
не добавлять вовсе: Android откатывается построчно, и получается одна русская фраза посреди
английского экрана.

## Деньги

Их нет. Есть добровольная карточка поддержки со ссылкой на Boosty — и всё: ни платной версии, ни
подписок, ни встроенных покупок, ни библиотеки биллинга, ни рекламы, ни пейволла, ни проверки
лицензии. Поддержка разработчика ничего не открывает, все возможности бесплатны, и карточка прямо об
этом говорит. Живёт она в настройках и один раз показывается на главном экране — после нескольких
проверок и с возможностью закрыть её навсегда.

## Имя пакета и класс базы

Пакет и `applicationId` — `app.vazovsky.permaware`, как и называется продукт. Переименование из
`app.vazie.permissionwatch` прошло до первого релиза: листинга в Play нет, установленных копий нет,
так что осиротеть было нечему. После публикации история была бы другой — смена `applicationId`
отвязывает все установки и требует нового листинга.

Класс базы при этом сохранил имя `PermissionWatchDatabase`. Путь выгруженной схемы выводится из
полного имени класса, и переименование пакета его уже один раз сдвинуло; двигать второй раз ради
того, чего пользователь не видит, незачем.

Единственная строка, которую человек вообще видит, — `R.string.app_name`.

Исходники открыты для чтения, изучения, аудита и оценки — но не для перевыпуска. Собирать из них

нельзя. Подробности в [LICENSE](LICENSE).
